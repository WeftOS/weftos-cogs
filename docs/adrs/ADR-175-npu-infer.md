# ADR-175: npu-infer, the node's NPU inference service

**Status:** Proposed
**Date:** 2026-10-25
**Cog:** `npu-infer` 0.1.0

## Context

The Ventuno Q has one NPU and 14 GiB of RAM. GenieX serves models on it over an OpenAI-compatible HTTP API with no authentication, loads a model on its first request, has no unload call, and keeps every model it has loaded until its keep-alive runs out. Measured on the board: Gemma 4 E4B is OOM-killed next to anything else, and two language models loaded together push the next load into the OOM killer (bench, 2026-10-25). The Stable Diffusion service (`weftos-sd.service`, :18700) and the Edge Impulse runners use the same NPU. Several cogs want language or vision models (`assistant`, `vision-describe`), and none of them should start GenieX or choose what stays in memory.

The Ventuno cog plan (4.5, 5.3) makes `npu-infer` the one owner of GenieX and gives other cogs a call address, `svc.infer/<node>`. WeftOS ADR-122 section 12 adds the request/reply primitive for it.

## Decision

1. **One owner.** The cog starts GenieX through its wrapper (`~/.local/bin/geniex`; the bare binary cannot find `libgeniex.so`) and is its only client. `src/http.rs` refuses any address that is not loopback, so a config cannot point it at a remote GenieX.
2. **One GenieX per resident model.** GenieX cannot unload a model, so each resident model is its own `geniex serve` on a loopback port from `--base-port` (18181) up, started with `--keepalive 86400` so GenieX never evicts on its own. Evicting a model is killing its process. Children carry `PR_SET_PDEATHSIG`, so a crashed or stopped cog leaves no model holding NPU memory. Two servers with different models were checked side by side on the board.
3. **Calls.** `svc.infer/<service>` (`--service`, default `venq-npu`) with the `infer.v1` body: `model`, `priority` 0..=9 (default 4), `text`, optional `system`, one optional image as either an inline `image_b64` (up to 40 K chars, with `image_mime`) or a `blob.v1` handle in `image_blob` (PNG or JPEG, up to 4 MiB, WeftOS ADR-122 section 13), `max_tokens`. A handle in the call is what grants this cog read access; the cog reads it with `blob_get` in 32 KiB slices just before the call runs, not when it queues, so a full queue holds handles and not megabytes, and a blob that cannot be read fails the call before any model is loaded for it. The reply body is `{model, text, finish, usage, queue_ms, load_ms, run_ms, loaded}`. The cog re-checks every rule of the schema, because the broker checks only the schema id.
4. **Catalog.** A call may name only a model in the catalog (built-in list of the models measured on the board, or `--catalog FILE`), by alias or exact GenieX id. Anything else is refused with the list of served aliases; a vision-less model refuses an image. Gemma 4 E4B is deliberately absent.
5. **Queue.** One worker runs one call at a time (the NPU is one resource; two concurrent models were the OOM). Highest priority first, a call for an already-resident model before one that needs a load within a priority, then arrival order, and a waiting call gains one level per 30 s so a stream of interactive calls cannot starve a background one. 64 calls may wait (`--queue`); more are refused as busy. A call whose deadline (the broker's `timeout_ms`) has passed is dropped unrun.
6. **Residency.** A model is admitted when resident costs plus its own stay within `--budget-mib` (8000), the resident count stays within `--slots` (3), and `MemAvailable` after the load stays above `--reserve-mib` (2048, which covers the image service, the daemon and builds). Room is made by evicting least recently used models. A model that cannot fit even with everything evicted is refused without evicting anything. Cost is the catalog estimate until the model has loaded, then the measured cost: the drop in `MemAvailable` across the load, floored by the server's own RSS, because NPU weights are DMA memory that RSS does not count. Measured costs are saved to `--state-dir/costs.json` and used on the next start.
7. **Failure.** A load that fails, or a server that has died, is killed and started again through the wrapper, and the call retried once; a second failure is reported with both messages. A model error (context too long, bad input) is reported as is and does not restart anything. The earlier symptom this answers: after about 13 hours GenieX returned `Model loading failed` for every request until a fresh process was started.
8. **The image service.** Before each call the cog reads the service's `/v1/health` on loopback and waits while it reports `busy`, up to the call's deadline. A service that is not running counts as idle. The e-ink art client keeps calling the service directly, so this cannot be a lock: it narrows the overlap to the length of one image. An `image.sd15` model class routed through this cog is not done; a 512x512 PNG is bigger than a service reply (64 KiB) until blobs (B5) exist.
9. **Reporting.** `telemetry/<service>` (`telemetry.v1`) every `--publish-secs` (5): `queue.depth`, `queue.oldest_wait`, `npu.busy`, `models.resident`, `mem.resident`, `mem.budget`, `mem.available`, `sd.busy`, one `model.loaded.<alias>` per resident model (value its cost in MiB), and the counters `calls.served/failed/rejected/expired`, `models.loads`, `models.evictions`, `geniex.restarts`. The node daemon turns these into `accel.npu.qualcomm` facts; the cog does not write facts itself.
10. **Wire.** The cog speaks the cogbus protocol directly (`src/bus.rs`: length-prefixed JSON on the socket from `WEFTOS_COGBUS` with the token from `WEFTOS_COGBUS_TOKEN`), so it stays a standalone package. It reconnects with backoff and serves again after a broker restart. A provider waiting for calls is silent, so the reader answers the broker's idle ping with a pong frame at once; a hello refused as `busy` (the per-instance cap of 8 connections) is retried like any other failure.
11. **`--simulate`** serves (or with `--once` answers one call) with a backend that runs no model; answers are marked `SYNTHETIC`. It exists for the gate and for protocol tests.

12. **Under placement** (found on the first real-broker run, 2026-10-26). The host starts a cog with a sanitised environment (no `HOME`) and applies `[resources].ram_mb` as an address-space limit on the cog and every child; the default is 256 MiB. GenieX is a Go program that reserves far more than that at start (`fatal error: failed to reserve page summary memory`) and exits without `HOME` ("$HOME is not defined"). So `cog.toml` declares `[resources] ram_mb = 65536` (the most the host allows; resident memory is bounded by `--budget-mib`, not by this), the cog starts GenieX with a cleared environment holding only `HOME` (from `--geniex-home`, else derived from the wrapper path `<home>/.local/bin/geniex`) and `PATH`, and a server that exits at start reports the first line of its own log in the error.

## Consequences

- GenieX is reachable only from the board's loopback, and only this cog talks to it. Loopback is the boundary, not authentication: another local process could still connect to 127.0.0.1:18181. That is the same trust as the rest of the board's local services; a per-uid firewall rule (`-m owner`) would close it and is a device change left to the operator.
- Evicting costs a reload: 7 to 12 s for a 1 to 4 B model. A workload that alternates two models that do not fit together pays that on every switch; the telemetry counters show it.
- Replies are one body of at most 64 KiB and there is no cancellation or streaming yet. `max_tokens` bounds a call.
- The cost measurement is one reading of `MemAvailable` before and after, so a build running at the same moment overstates it. That errs toward evicting, and the next load measures again.
- The Edge Impulse model runners (YOLOX, keyword spotting) are not started by this version; the plan has this cog start them, which needs a catalog of runner kinds and is the next step.
- The cog is `interfaces = ["npu"]`. It opens no other bus.

## Verification

Unit tests cover the queue order and aging, residency (LRU, count limit, over-budget refusal, the system reserve, measured costs), the scheduler against a fake backend (priority order, one at a time, eviction, restart on a failed load, restart on a dead server, refusal of an unknown or oversized model, expiry, the image service gate, two consumers with different models), the HTTP client, the GenieX backend against an in-process fake server, the bus framing, and the telemetry names. `tests/cli.rs` runs the binary against a stand-in broker with the synthetic backend. WeftOS `crates/weftos-cogbus/tests/svc.rs` runs the call primitive against the real broker. The on-board run is recorded in the card.
