# ADR-174: BME680 environmental reader cog

**Status**: Proposed
**Date**: 2026-10-05
**Cog**: `bme680` 0.1.0

The number 174 is provisional. It was free in this repo and in the sibling cogs worktrees checked on 2026-10-05 (the highest committed cog ADR here is 166). It is reassigned if this cog is exported upstream.

## Context

The part is a Bosch Sensortec BME680 on a purple breakout, chip marked BME680, described from the owner's New Modules album. This lane did not open that album. I2C, not UART. The nearest cog is `sen0628-tof` (I2C on `/dev/i2c-1`, fail-honest `no_source`, loopback-or-export, guide). This cog does not report geometry.

RuView ADR-384 (proposed, 2026-10-05) splits perception evidence (`spatial.evidence.v1`) from object readings (SenML, RFC 8428). Temperature, humidity, pressure and gas resistance are the state of an object. They are not evidence a person is present.

## Decision

1. **Protocol source.** Bosch Sensortec, "BME680 Low power gas, pressure, temperature & humidity sensor", document number BST-BME680-DS001-09, revision 1.9, February 2024. Fetched from `https://www.bosch-sensortec.com/media/boschsensortec/downloads/datasheets/bst-bme680-ds001.pdf` on 2026-10-05 (PDF 1.7, 1.3 MB). Not committed.

   Calibration byte signedness and block lengths also follow Bosch's BME68x Sensor API v4.4.8, commit `80ea120a8b8ac987d7d79eb68a9ed796736be845` (`get_calib_data` in `bme68x.c`, BSD-3-Clause). The formulas that produce the published numbers are the datasheet's floating-point forms, not a copy of that C file. The API's float gas functions do not match datasheet §3.4.1; they are not used. The API's `bme68x_get_meas_dur` is used only as a wait hint.

   | Fact | Value | Source |
   |---|---|---|
   | I2C address | `0x76` if SDO is GND, `0x77` if SDO is VDDIO. SDO must not float. | §6.2 |
   | I2C vs SPI | CSB at VDDIO selects I2C. CSB low at power-up locks SPI until power-on reset. | §6.1 |
   | Chip id | `0x61` at I2C `0xD0` | §5.3.1.6, Table 20 |

2. **Reads, plus the forced-mode trigger.** The chip powers up in sleep and does not measure until mode is written. The only writes are §3.2.1: `ctrl_hum`, `ctrl_meas` (sleep, so oversampling is latched), `ctrl_gas_0` (heater current allowed), `res_heat_0`, `gas_wait_0`, `ctrl_gas_1`, `ctrl_meas` (forced). Soft reset `0xE0 = 0xB6` is never written. The address is never changed. SPI page, `idac_heat` and the IIR filter are left alone.

3. **Fail honest.** No device, no chip id `0x61`, or no `new_data_0` produces one status object with `health: "no_source"`, four nulls, and an `error` that names the bus and the address. Exit 0 for `--once`. A clear `gas_valid_r` or `heat_stab_r` omits gas resistance. It is not reported as 0 Ω. Stale data registers are not published.

4. **SenML object readings (ADR-384 §4).** One JSON array per line. `bn` is `--source-id` (default `bme680/`), the installed board's object id, not the catalog type `bme680-breakout`. `proof_` is repeated on every record: `MEASURED` for a real sample, `SYNTHETIC` for `--simulate`. `t` is Unix seconds on every record. Units: `temperature`/`Cel`, `humidity`/`%RH`, `pressure`/`Pa`, `gas_resistance`/`Ohm`. `--simulate` feeds a fixed calibration image and ADC field through `decode_calib`, `decode_field` and `compensate`. It does not open I2C.

5. **No spatial evidence.** ADR-107's records (`shell_measure`, `pose`, `radar_track_point`, `rf_link_observation`, `rf_gaussian`, `uwb_echo`, `imu_event`, `human_confirm`) do not fit these quantities. ADR-384's accepted perception types add `radar_range` and `tof_depth` and still have none. This cog does not compile a `spatial-evidence` feature, does not emit `spatial.evidence.v1`, and does not mint a track or an AABB. A reading is not a person. `gas_resistance` is not in ADR-384's example name list; unknown names are stored and counted, not treated as presence. There is no external vital-sign record here either (ADR-384 §3): this part reports none.

6. **Status line.** Separate JSON object, schema `weavelogic.cog-output.v0`, `health` `ok` | `degraded` | `no_source`. The pack is the next stdout line, or `--readings-out`. `source.verified` is false until a bench comparison exists. No store vector: these values are not an embedding.

7. **Export.** `127.0.0.1:8057` only. `GET /status`, `GET /readings`, `GET /guide`. `/readings` is a JSON object with `"readings": null` when there is no pack, never an empty array. The listener starts before the sensor is opened.

8. **Guide.** `guide/` schema 1, served at `GET /guide`. 3.3 V only. A Seed reboot does not drop 3V3.

9. **Category** `signal`. Not `presence`.

## Non-claims

- Not a gas alarm, not a CO2 meter, not IAQ, not BSEC. Datasheet §4 says those indexes come from BSEC. This cog does not run it.
- Not medical. Not a safety device.
- `null` means not reported. It does not mean zero.
- Chip id `0x61` does not by itself prove the mark is BME680. The BME68x API v4.4.8 describes itself as the API for the BME680 and the BME688 and uses the same id constant. This datasheet does not define the variant register the API reads at `0xF0`. This cog does not read it and does not implement BME688 scan mode.
- Vendor accuracy figures are not our measurements.
- `CODE` is not emitted. `--simulate` is `SYNTHETIC`, which ADR-384 says is not ground truth.

## Verification

Unit tests in `src/compensate.rs`: datasheet `gas_wait` example `0x59` for 100 ms; quick-start `ctrl_meas` bytes `0x54` then `0x55`; calibration and ADC bytes decode to the chosen coefficients (`temp_adc` 519888, and the rest named in the test); float formulas on that image give about 31.589 °C, 95523.80 Pa, 80.282 %RH, 545243.8 Ω; heater code 150 at 300 °C and 25 °C ambient; gas omitted when `gas_valid_r` or `heat_stab_r` is clear; skipped temperature does not invent pressure or humidity; short blocks and a clear `new_data_0` are refused.

`src/senml.rs`: `proof_` on every record, `bn` only on the first, units as above, no pack when every quantity is missing, no zero standing in for gas.

`src/sensor.rs`: address other than 0x76/0x77 refused before `open`; a missing `/dev` node names the path and address; `--simulate` is the same decoder.

`tests/cli.rs`: `--help`; unknown arguments and `--spatial-out` exit 2 with empty stdout; `--device /etc/hosts` refused; bad address refused; `--source-id` without `/` refused; `--once` on a missing device is one `no_source` line, nulls, exit 0, under 15 s; `--once --simulate` is two lines, `SYNTHETIC`, the formula values; `--readings-out` keeps the pack off stdout.

Guide page list matches `guide.toml`.

**Not yet tested on hardware.** No MEASURED block. No Seed firmware, no sha256 of a sideloaded binary, no comparison with a reference instrument.

## Consequences

- Dependencies: `libc` for `I2C_RDWR`, plus `serde` / `serde_json` and `cog-sensor-sources` (help text only). No `tokio`, `reqwest`, `hyper`, or `clap`. No WeftOS or RuView crate.
- The catalog fragment `src/cogs/bme680/catalog-fragment.json` names module `bme680-breakout` (vendor Bosch Sensortec). `catalog.json` in the WeftOS tree was not edited.
- I2C enablement, if `/dev/i2c-1` is missing, is an owner approval for the seed operator. This cog does not SSH and does not edit boot files.
- First-sample heater ambient is hardcoded at 25 °C (§3.3.5 allows a hardcoded ambient). Later samples reuse the previous temperature when it fell inside −40 °C to 85 °C.

## UNKNOWN

- Purple-board silkscreen, SDO strap, CSB strap, and whether a regulator sits between the header and the chip. Not visible to this lane. The guide says 3.3 V only until that is seen.
- Whether a BME688 would compensate correctly under these BME680 formulas. Not tested, and not separated by a register this datasheet defines.
- Whether `heat_stab_r` is set at 300 °C / 100 ms on this breakout.
- Compensation against a reference thermometer, hygrometer or barometer.
- Linux `I2C_RDWR` on the Seed's bus. The datasheet allows a repeated start. It has not been run here.
